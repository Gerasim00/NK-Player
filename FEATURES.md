# NK Player — функционал

Актуально для версии **1.5.0**. Список составлен по коду (`renderer.js`, `main.js`,
`vk-audio.js`, `song-cache.js`, `local-music.js`, `library.js`, `updates.js`,
`discord-rpc.js`, `index.html`), а не по обещаниям релизов.

---

## Вход и аккаунт

- Вход через встроенное окно `vk.ru/login` с QR-кодом: сканирование в приложении
  ВК на телефоне. Статус проверяется раз в секунду по куке `remixsid` / `remixnsid`.
- Пользовательское соглашение на экране входа: текст можно свернуть/развернуть,
  чекбокс обязателен, версия текста хранится в `localStorage` (`nk.termsVersion`) —
  при смене версии соглашение спрашивается заново.
- Профиль в сайдбаре: имя, `@screen_name`, аватар; имя дублируется в титульной панели.
- Выход из аккаунта: очищает storage сессии, очередь, кэш-хиты и сохранённое
  состояние воспроизведения.
- Миграция старого профиля `VK Music Player` → `NK Player` при первом запуске,
  чтобы вход в ВК не слетал после переименования приложения.

## Разделы

| Раздел | Содержимое |
|---|---|
| **Главная** | Сцена с голограммой кота, подиум со спектрографом, большая кнопка play |
| **Моя музыка** | Все треки ВК; в подзаголовке количество и общая длительность |
| **Загруженная музыка** | Свои файлы, кнопка «＋ Добавить», счётчик в сайдбаре |
| **Результаты поиска** | Поиск по ВК, кнопка «Показать ещё» для догрузки |
| **Артист** | Открывается кликом по имени исполнителя |
| **Очередь** | Предстоящие треки окном до 50 позиций |
| **Плейлисты ВК** | Из профиля, с обложкой, автором и числом треков |
| **Свои плейлисты** | Отдельной группой сверху, хранятся локально |

## Плейлисты

- Свои плейлисты: создать (＋ в сайдбаре), переименовать, удалить,
  добавить трек, убрать трек.
- Файл `userData/playlists.json`; ВК не даёт создавать плейлисты без OAuth-токена,
  поэтому свои хранятся в профиле приложения.
- Трек хранится снимком: `id`, `reloadId`, название, исполнитель, длительность,
  обложка. Прямые ссылки не сохраняются — они живут час.
- Обложка плейлиста — от первого добавленного трека.
- Контекстное меню: правый клик по плейлисту в сайдбаре или кнопка «⋯».

## Плеер

- Нижняя панель: обложка, название, исполнитель; название трека уходит в
  заголовок окна и в Media Session.
- Play/pause; вперёд; назад (при позиции > 3 с возвращает в начало трека).
- Перемотка: полоса 0–1000, время текущее и общее.
- Громкость с запоминанием, кнопка mute (🔇 / 🔉 / 🔊).
- Shuffle и повтор: `off → all → one`, состояние сохраняется между запусками.
- Кнопки **EQ** (эквалайзер) и **DC** (Discord) в правой части панели.
- Большая кнопка на главной: продолжает текущий трек, а без него запускает
  «Мою музыку» с первого доступного трека.

## Очередь

- «Добавить в очередь» (≡ на строке трека) и «Воспроизвести следующим»
  (правый клик по треку).
- Новый трек встаёт сразу после играющего.
- Удаление из очереди по реальной позиции в порядке воспроизведения.
- Текущий трек убрать нельзя — вместо этого тост.
- Перемешивание в панели очереди тасует уже собранный порядок, а не собирает
  список заново.
- Счётчик у «Очереди» в сайдбаре показывает число предстоящих треков (до 50).

## Эквалайзер

- 10 полос: 31, 62, 125, 250, 500, 1000, 2000, 4000, 8000, 16000 Гц, по ±12 дБ.
- Preamp: −12…+6 дБ.
- Пресеты: Плоско, Бас, Бас+, Вокал, Рок, Поп, «Тише ночью».
- Отдельный выключатель питания и сброс; настройки сохраняются автоматически.
- Цепочка построена на Web Audio; при выключении фильтры прозрачны, а общий
  гейн возвращается ровно к 1.0.

## Звук и настройки воспроизведения

- **Кроссфейд** 0–12 с, по умолчанию выключен. Переход **последовательный**:
  старый трек гаснет по косинусу до нуля, затем новый нарастает по синусу.
  Дорожки никогда не звучат одновременно.
- **Нормализация громкости** — AGC по RMS с целью ≈ −18 dBFS, гейн 0.5–3.0,
  шаг раз в 400 мс; замирает на время перехода, чтобы не «дожимать» вручную
  собранный уровень.
- **Усиление баса** 0–12 дБ.
- **Surround-виртуализация** — расширение стереобазы (Haas).
- **Затухание при паузе** (~220 мс вместо резкого стопа), включено по умолчанию.
- Сброс всех настроек к значениям по умолчанию.
- Окно настроек разбито на группы с панелью навигации слева:
  «Воспроизведение», «Спектрограф», «Служебное», «Обратная связь»,
  «О программе». Показывается одна группа за раз; выбранная запоминается
  до закрытия приложения.
- «О программе»: логотип, версия из `package.json`, короткое описание, блок
  «ВНИМАНИЕ!» о том, что не синхронизируется с ВК (свои плейлисты, загруженная музыка, очередь,
  эквалайзер и настройки) и две кнопки-ссылки внизу — Discord и GitHub.
  Пункт навигации прижат к низу колонки. Открываются в системном браузере
  через `app:openExternal` (белый список: `github.com`, `discord.gg`,
  `discord.com`).

## Главная сцена и спектрограф

- Голограмма кота — готовая картинка `assets/holo-cat.png` с прозрачным фоном
  и линейным «дыханием» 5.2 с. Векторный кот и canvas-частицы отключены.
- Подиум с кольцом; лучи — фиксированные точки, бас по бокам, верха
  спереди/сзади. Троттлинг ~30 fps, `dpr ≤ 1.25`.
- Фон: звёзды, восходящие искры, сканлайны.
- Настройки спектрографа: толщина лучей, длина, количество лучей (24–96,
  по умолчанию 52), плотность точек, интенсивность баса/середины/верхов,
  включение и отключение всей группы.

## Обратная связь

- Группа «Обратная связь» в настройках: оценка плеера звёздами 1–5
  (клик по звезде, выбранная подсвечивается), поле для отзыва и предложений
  на 1200 символов со счётчиком «N / 1200» и кнопка «Отправить».
- Отзыв и оценка обязательны; пустая форма не отправится, ошибки и успех
  показываются рядом с кнопкой и гаснут через 5 секунд.
- Отзыв уходит в Discord-канал разработчика через webhook: embed со звёздами,
  названием оценки («Отлично» … «Очень плохо»), цветом по оценке, текстом
  отзыва и подписью «NK Player v<версия>». Упоминания в тексте отключены
  (`allowed_mentions: parse: []`), таймаут запроса 15 с.
- Отправка идёт через IPC `feedback:send` в main-процесс: renderer не знает
  адрес. Webhook в исходниках не хранится открытым текстом: XOR-шифрованный
  ключ лежит в `feedback.key`, файл добавлен в `.gitignore` (в репозиторий не
  попадает), но пакуется в сборку (`build.files`). Без файла отправка честно
  откажет с понятной ошибкой; для отладки можно задать переменную окружения
  `DISCORD_WEBHOOK_URL`.

## Постоянный кэш треков

- Файлы в `userData/song-cache`, давность использования хранится в
  `index.json` (запись отложенная, дописывается при выходе). LRU-чистка идёт
  по этому журналу, а не по mtime файла: mtime врёт после копирования профиля.
- Лимит 50 МБ – 5 ГБ (по умолчанию 2 ГБ), показ занятого места, ручная очистка.
- Чистка срабатывает при старте (лимит мог уменьшиться, пока приложение было
  закрыто), при смене лимита, после каждой докачки и раз в 5 минут. Вытесняется
  не «ровно до лимита», а до 90 % — иначе каждый новый трек выбивал бы ровно
  один старый.
- Текущий трек и три следующих по очереди не вытесняются (`cache:pin`).
- Файл снимается с учёта только после успешного удаления: на Windows играющий
  файл отдаёт `EBUSY`, и раньше запись исчезала из индекса, оставаясь на диске
  и занимая место, которое кэш считал свободным. Такой файл дожидается
  следующего прохода.
- Учёт идёт по имени вида `123_456.<ext>` с любым расширением (включая mp4 из
  `.mp4`-ссылок); статистика считается по факту на диске, а не по индексу.
- Качается текущий трек и до двух следующих; параллельно максимум 3 загрузки.
- Кэшируются только прямые mp3/aac (не HLS). Готовый файл играет с `file://`
  мгновенно и без сети.
- Оборванные загрузки не остаются мусором: `.part` старше часа подметаются,
  файлы меньше 1 КБ выбрасываются.
- Сетевой кэш Chromium ограничен 64 МБ, аудио-ответы отдаются с `no-store`,
  чтобы те же mp3 не лежали на диске второй раз. Его объём показывается в
  «Служебном» отдельной строкой; раздутый кэш от прошлых версий чистится при
  старте, кнопка «Очистить» сносит и его.

## Локальная музыка

- Импорт через диалог или перетаскиванием файлов в окно.
- Форматы: mp3, m4a, aac, flac, wav, ogg, opus, wma, mp4.
- Файлы копируются в профиль приложения. ID3-теги (TIT2 / TPE1 / TALB / APIC)
  читаются только для mp3; иначе название и исполнитель угадываются из имени файла.
- Обложка из тега сохраняется рядом; длительность подхватывается после первого
  проигрывания и запоминается.
- Удаление файла из библиотеки вместе с его обложкой.

## Поиск и работа со списками

- Поиск по Enter, догрузка результатов кнопкой.
- Фильтр по текущему списку (строка в хедере, задержка 150 мс).
- Виртуализация списка: при более чем 300 строках в DOM живёт только видимое
  окно плюс 8 строк запаса, прокрутка нативная.
- Индекс обложек по паре «артист + название»: пустые обложки в плейлистах и
  поиске заполняются из «Моей музыки».
- Строка трека: номер, который при наведении превращается в ▶; обложка с ленивой
  загрузкой и одним повтором при ошибке; буква-заглушка, если обложки нет.
- Контекстное меню трека: в очередь, следующим, в плейлист, «Все треки: артист»,
  убрать из плейлиста.
- Тосты-уведомления, заглушки с действиями для пустых списков и ошибок.

## Discord Rich Presence

- Тип активности «Слушает», исполнитель и название, иконки play/pause.
- Таймстемпы отправляются только во время воспроизведения: на паузе Discord
  всё равно продолжил бы считать время.
- Кнопки «Слушать в ВК» нет.
- Троттлинг 4.5 с, повторная отправка одинакового статуса не тратит лимит,
  переподключение каждые 15 с, есть кнопка полного выключения (DC).
- Обложка трека в статусе отключена флагом `USE_COVER_ART = false` в
  `discord-rpc.js` — используется статичный логотип.

## Обновления

- Проверка через GitHub Releases репозитория `Gerasim00/NK-Player`.
- Результат кэшируется на 6 часов; неудачные попытки не кэшируются.
- Автопроверка через 2 с после старта, баннер «Доступна новая версия»,
  кнопка «Проверить» в сайдбаре и в настройках.
- Окно обновлений: скачивание с прогрессом, сверка размера, затем тихая
  установка `NSIS /S` с выходом из приложения.

## Окно и горячие клавиши

- Своя титульная панель вместо рамки Windows; свернуть, развернуть, закрыть,
  кнопки настроек и обновлений.
- Стартовый размер 1240×820, минимум 900×560.
- `Space` — play/pause; `←` / `→` — ±5 с; `Ctrl+←` / `Ctrl+→` — предыдущий и
  следующий трек; `Ctrl+F` — фокус в поиск; `Ctrl+E` — эквалайзер;
  `Esc` — закрыть панель, меню или модальное окно.
- Media Session: метаданные трека и системные кнопки play/pause/next/prev.

## Восстановление сессии

- Очередь, порядок воспроизведения, позиция и трек восстанавливаются в нижнюю
  панель при запуске. Звук сам не включается.
- Позиция внутри трека пишется каждые 4 секунды и при перемотке, а при
  возобновлении не допрыгивает до самого конца.

## Под капотом (влияет на поведение)

- Работа через `al_audio.php` на куках сессии и расшифровка ссылок вида
  `audio_api_unavailable.mp3?extra=…`.
- Приоритет прямых `okcdn`-стримов, запасной путь — `reload_audio` пачками до 10.
- Кэш ссылок на час (`URL_TTL`).
- Прогрев самозалитов: ВК собирает HLS по первому запросу за 15–40 с, поэтому
  заранее делаются два GET по 64 КБ; до 500 треков за сессию.
- Обработка квоты ВК (~400 ссылок за окно): паузы 6 / 15 / 30 / 60 / 60 с и
  автоматическое продолжение очереди.
- Подмена заголовков и CORS для аудио-CDN, чтобы hls.js работал из окна `file://`.

## Чего в плеере нет

Текстов песен, скачивания треков в файл (есть только внутренний кэш),
истории прослушиваний, системного трея, глобальных горячих клавиш вне окна,
полноэкранного режима, загрузки своих треков в ВК, скробблинга, таймера сна,
динамической визуализации вместо статичной голограммы, ручной замены обложек.
